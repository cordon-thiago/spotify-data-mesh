## Implementation Strategy

- **MVP**: Phases 1, 2 and 3 (User Story 1). That already stops the one irreversible failure: personal data or a secret reaching the public repository. Stop and review there if time is short.
- **Incremental**: add US2 (quality of files), then US3 (the part nobody can skip), then US4 (docs and single definition), then Polish.
- **Order matters**: existing files are made green in Phase 2 *before* the hooks exist, so the first `make lint` is green (FR-017). Never loosen a hook to make an old file pass; fix the file or add one narrow, reasoned allowance.
- **Safety**: every database step uses the throwaway project `smesh-ci`; the owner's database and `.env` are read for a row count only. If anything touches or would touch `data/`, stop.
- **Commits**: none unless the owner asks. When asked, group as: tooling config and fixes of existing files; US1; US2; US3; US4 and docs (conventional messages, English, `Co-Authored-By` line from the session reminder).
